## 二、真缺陷明细

### G1【阻断】通行字层（第三层 cmap）错映：常用字显示成别的字

- **现象**：陈昌治、徐锴、藤花树三款输入「二」显示的是「上」的小篆；「光」→「水」、「煙」→「完」、「關」→「寡」、「親」→「榛」、「詳」→「翔」、「壹」→「一」、「面」→「麪」。证据：[通行字错映-陈昌治本.png](证据/通行字错映-陈昌治本.png)（第一行是输入通行字的实际显示，第二行是《說文》字头码位应有的字形，第三行是被借形那个字的本字，与第一行同形）。
- **范围**：`data/modern_map.tsv` 共 12,271 条。其中「字符本身就是《說文》字头（`seal.db` sw_pos 有登记），却映射到另一个隸定字的码位」的有 107 条，清单见 [通行字错映-精筛.tsv](数据/通行字错映-精筛.tsv)。sw_pos 自身有错位噪声（例如「欣」一类相邻字头错一位），所以 107 条是**疑似清单**，需要逐条复核；上面 8 例已用字形目检确认。
- **复现**：
  ```bash
  hb-view --font-size=96 -o /tmp/g1.png audit/_release/ShuowenSeal-ChenChangzhi.otf "二光煙關親詳壹面"
  cd ../zhuan && .venv/bin/python -m zhuan -d "二光煙關親詳壹面"   # 显示命中路径
  ```
  查表链输出 `二 → 上 [变体链 二→上]`、`光 → 水 [变体链 光→𬺧→水]`、`親 → 榛 [变体链 親→亲→榛]`。
- **成因**：`modern_map.tsv` 由 zhuan 查表链导出，查表链让**变体链优先于字头本字**。「二」本身就是《說文》字头（二部，`sw_pos: 二 → U+3F850`，四款都有字形），但因为 `sw_variants` 里有「二 是 上 的古文」这条关系（`二|sw_gw|上`），被变体链带到了「上」。另外多跳链（光→𬺧→水、親→亲→榛）在中间环节语义发生了漂移。
- **建议**：zhuan 查表链的优先级改为「隸定本字 → 《說文》字头（sw_pos）→ 变体链」；变体链排除 `sw_gw`（古文从属）这类不表示同字的关系，并限制跳数（建议 ≤1，或只走 sem/trad/simp）；修好后重新导出 `modern_map.tsv`。fonts 侧把这 107 条和常用字频表做成回归清单（见脚本报告门禁 Q6）。

### G2【阻断】段玉裁本「二」「上」空白：错映、官方缺口、空白 `.notdef` 三者叠加

- **现象**：段玉裁本输入「二」「上」都是空白。证据：[一二上-四款-release.png](证据/一二上-四款-release.png)（第二行为段玉裁本）。
- **核实（PDF 原表）**：第 2 页 U+3D008（上）格只有 `TH-00008 C-00008 K-00008`，**没有 D 编号**；`D-00008` 在 U+3D006（丄）格，`D-00007` 在 U+3D007（𠄞，古文上）格。这和段注改「上」篆作「丄」的学术处理一致。结论：**段玉裁本缺 U+3D008 是官方数据缺口，不是提取缺陷**；font-lead 交接时的判断（SealSources 中 dyc 列为空）正确。
- **为何空白**：G1 把「二」错映到 U+3D008，段玉裁本没有这个码位的字形，cmap 不收「二」「上」；渲染器回退到 `.notdef`，而本字体的 `.notdef` 没有轮廓（G7），于是显示空白。浏览器、系统输入法等有字体回退的环境会显示成别的字体的「二」，所以只在单字体环境（PIL、hb-view、海报管线）下表现为「整字空白」。
- **复现**：
  ```bash
  hb-view --font-size=128 -o /tmp/g2.png audit/_release/ShuowenSeal-DuanYucai.otf "一二上"
  uv run --offline python -c "from fontTools.ttLib import TTFont;c=TTFont('audit/_release/ShuowenSeal-DuanYucai.otf').getBestCmap();print([hex(x) for x in (0x4E8C,0x4E0A,0x3D008) if x in c])"   # → []
  ```
- **建议**：① G1 修好后「二」应映射到 U+3F850，段玉裁本有字形（D-09755），「二」的问题随之解决；② 「上」在段玉裁本的处理：**推荐**按本款借形到 U+3D006（段本 D-00008 即段注所定「上」篆「丄」），作为「分款回退表」写进 data/ 并在文档中标注；不建议跨款借别家字形（会混淆版本）；③ `.notdef` 画成方框（G7），以后的缺口一眼可见。

### G3【严重】PDF 第 190 页整页漏提（四款）

- **现象**：码表共 190 页，管线只处理第 1–189 页。第 190 页 205 个标注全部漏提：陈昌治 54、徐锴 48、段玉裁 48、藤花树 55。连带受影响的有：通行字层 41–48 个/款（GB2312 常用字 17–23 个：亥、尊、戌、酋、酢、酣、酬、酸、醉、醋、醒、醐……）、隸定字层 48–55 个/款。
- **复现**：`uv run --offline python audit/工具/漏提诊断.py`（输出「第190页不在 PAGES」）；`hb-view --font-size=96 -o /tmp/g3.png audit/_release/ShuowenSeal-XuKai.otf "醉酸尊酬"` → 空白。
- **成因**：`build_fonts_svg.py:38` `PAGES = range(1, 190)` 的上界是开区间，少一页。按现有的定位规则，这 205 个全部能唯一命中（已验证可回收 205/205）。
- **建议**：页数改用 `doc.page_count`；构建增加「每款提取数＝映射表编号数」的门禁（脚本报告 Q2）。

### G4【严重】藤花树本 TH-X／TH-Y 编号系列整批漏提

- **现象**：藤花树本应有 11,328 码位，实际只提取到 10,641 个。漏提共 687 个：X 系列 396、Y 系列 236，另外 55 个在第 190 页（其中 7 个同属 X/Y）。连带通行字层缺形 729、GB2312 常用字缺形 **343** 个（丽、些、亮、低、倒、别、办、势、劬……）。
- **复现**：`uv run --offline python audit/工具/漏提诊断.py`（输出「编号被 TOKEN_RE 拒收（X/Y 系列）: 632」）；`hb-view audit/_release/ShuowenSeal-TengHuaShu.otf "丽些亮低倒别办"`。
- **成因**：`build_fonts_svg.py:42` `TOKEN_RE = r"^(TH|C|K|D)-(\d{4,6})$"` 只接受纯数字编号，而 seal_sources 和 PDF 里藤花树本另有 `TH-X001…`、`TH-Y001…` 两个系列（PDF 标注照常存在，例如 3D007 格的 `TH-Y001`）。放宽正则后，按现有定位规则 639/639 都能唯一命中。
- **建议**：正则改为 `^(TH|C|K|D)-([XY]?\d{3,6})$`，同样受 Q2 门禁兜底。

### G5【严重】扁宽字形垂直浮顶：「一」只是最极端的那一个

- **现象（Release）**：受宽度约束（宽高比 > 0.98/0.96）的字形一律顶对齐到 0.86em，墨迹中心高于字面中线 0.38em。

  | 款 | 宽约束字形 | 垂直偏 >2% em | >5% | >10% | 「一」 | 真「二」U+3F850 |
  |---|---|---|---|---|---|---|
  | 陈昌治本 | 8 | 7 | 3 | 1 | +39.1% | +4.5% |
  | 徐锴本 | 468 | 239 | 81 | 13 | +41.5% | **+18.3%** |
  | 段玉裁本 | 70 | 37 | 12 | 5 | +42.9% | +2.1% |
  | 藤花树本 | 3 | 3 | 1 | 1 | +43.8% | +0.0% |

  证据：[一字四款-Release.png](证据/一字四款-Release.png)；[扁宽字形垂直浮顶-徐锴本.png](证据/扁宽字形垂直浮顶-徐锴本.png)（上为 Release，下为本地 WIP：**WIP 只把「一」压回中线，「二」（U+3F850）、U+3D079、U+3FB70、U+3D3A6、U+3FBAD 依然浮顶**）。
- **复现**：`uv run --offline python audit/工具/垂直对照.py 浮顶.png "audit/_release/ShuowenSeal-XuKai.otf=Release" -- 3D000 3F850 3D079`；逐字数据见 `audit/数据/release-*.tsv` 的「垂直偏」「约束」列。
- **成因**：`build_ttf_from_paths.py:200`（HEAD）`ty = TOP*UPEM - ry1*s2` 顶对齐。只有高度约束的字形（缩放后高恰为 0.96em＝TOP−BOT），顶对齐才等价于居中；宽度约束的字形一律上浮 (0.96 − 缩放后高)/2。WIP 只给缩放后高 < 0.5em 的字形改为居中，**全库只有「一」落在这个区间**（每款恰好 1 个）；高度在 0.5–0.96em 之间的 282 个字形照旧浮顶，而且 0.5em 处存在最大 0.23em 的跳变。
- **建议**：去掉分支，**无条件**按字面中心垂直居中：`ty = (TOP+BOT)/2*UPEM − (ry0+ry1)/2*s2`（高度约束时与原式等价，不会影响其余约 4 万个字形）。

### G10【严重】隸定字层重码：先到先得，常用字落到异体或古文字形

- **现象**：`seal_sources.tsv` 中有 94 个隸定字被两个以上小篆码位共用（例如王、殺、皮、謀各有两个码位）。第二层 cmap 用 `setdefault` 按码位升序填充，结果总是取**码位最小**的那个。如果这个字本身是《說文》字头，而字头码位不是最小的那个，用户输入它看到的就是异体或从属字形：一共 33 条，见 [映射审计.tsv](数据/映射审计.tsv) 中的「隸定层错映」行。已目检：输入「白」显示的是 U+3DA0E（自部所收的「白」，形近「自」），不是白部字头 U+3E657；「舌」显示的是 U+3D660，不是舌部字头 U+3D429。证据：[隸定层重码-陈昌治本.png](证据/隸定层重码-陈昌治本.png)。「鼓」在鼓部、攴部各有字头，属于本来就有歧义的情况，需要人工判定。
- **复现**：`hb-view --font-size=110 -o /tmp/g10.png audit/_release/ShuowenSeal-ChenChangzhi.otf "白舌"`。
- **成因**：`build_ttf_from_paths.py:141-145` 第二层按码位升序 `setdefault`，没有任何优先级依据。
- **建议**：第二层重码时，优先取 sw_pos 字头码位；sw_pos 无法判定的，进入人工裁定表（data/ 下新建「重码优先表」）。注意 sw_pos 本身有错位噪声，33 条要人工复核后再固化。

### G6【轻微】源字形碎屑撑大包围盒，导致主体缩小或偏心

- **现象**：码表源字形中有面积 < 0.02% em² 的游离小点（扫描尘点），段玉裁本最多，773 个字形共 869 粒，其中 756 个与源完全一致，是**源字形本身带的**（证据：[段玉裁本碎屑抽样.png](证据/段玉裁本碎屑抽样.png)，左侧 PDF 原形中可见同样的小点）。其中 33 个字形的碎屑落在主体外侧、把包围盒撑大超过 1% em，度量归一按被撑大的包围盒计算，主体随之偏心或缩小：段玉裁本 31 个（最大偏心 4.9% em，如 U+3D9FB、U+3E90D、U+3F640），陈昌治本 U+3E27D（主体被缩小约 8%），藤花树本 U+3DB90。
- **清单**：[碎屑污染包围盒.tsv](数据/碎屑污染包围盒.tsv)，以及全部碎屑字形 [段玉裁碎屑字形.txt](数据/段玉裁碎屑字形.txt)。
- **复现**：`uv run --offline python audit/工具/对照图.py x.png dyc:3D9FB dyc:3E90D ccz:3E27D`。
- **建议**：度量归一时先剔除面积 < 0.02% em² 的游离外轮廓再求包围盒（至少在求包围盒时排除）；是否把碎屑从字形中删掉属于字形保真的取舍，建议删掉并在文档中注明「已去除码表扫描尘点」。

### G7【轻微】`.notdef` 为空白字形

- **现象**：`.notdef` 没有轮廓（`BoundsPen` 结果为 None）。缺字时显示为空白，而不是方框（「豆腐块」），G2 这类缺口因此被伪装成「空字形」。
- **建议**：`.notdef` 画一个空心矩形（常规做法）。

### G8【轻微】度量与元数据

| 项 | 现状 | 问题 | 建议 |
|---|---|---|---|
| usWinDescent | 204 | 墨迹最低到 −205，Windows 按 usWin 裁切会少 1 单位 | 用 `round`，不要用 `int` 截断；或加 1–2 单位余量 |
| 行高 | ascender 1761／descender −204，lineGap 0，总计 0.96em | 墨迹恰好填满行框，多行文本上下行墨迹相接 | typo 行距至少 1.0em，或给 lineGap；设置 USE_TYPO_METRICS 位 |
| 竖排 | 没有 vhea/vmtx | 宣发古诗竖排依赖渲染器的回退值 | 补全角竖排度量（advanceHeight＝UPEM，tsb 按字面区居中） |
| name | 没有 ID 3（唯一标识）、ID 5（版本）；ID 13 的中文文本挂在英文语种 0x409 下 | 版本不可辨；许可文本语种标错 | 补 ID 3/5（与 Release 版本号一致）；ID 13 中文挂 0x804，英文另写一份 |
| head.fontRevision | 1.0 | 与 v0.1.1 不一致 | 同步版本号 |
| OS/2 | fsSelection＝0（REGULAR 位未置）、ulCodePageRange1＝0、achVendID＝`????` | Windows 字体列表/回退中可能不归入中文字体 | 置 REGULAR 位、代码页置简繁中文位、填厂商标识 |
| post | 格式 2（CFF 字体通常用格式 3） | 体积冗余 | 可改为格式 3 |
| 可复现性 | head.created/modified＝构建时刻 | 同源两次构建的哈希不同 | 支持 SOURCE_DATE_EPOCH |

### G9【可接受】亚单位发丝缝在整数化后的拓扑变化

- **现象**：与源路径相比，148 个字形的轮廓拓扑有变化（陈昌治 15、徐锴 26、段玉裁 81、藤花树 26）：近接笔画粘连（外轮廓合并）或近闭合的空间被闭合（新增孔洞，如徐锴本 U+3E526 宀部被闭合；段玉裁本 U+3E186 交叉处出现一个约 5 像素@96px 的小孔，是斑洞疑似中唯一一例「真孔洞且源中没有」）。这些字形的面积差全部 < 0.3%，800dpi 对照肉眼看不出差别。证据：[斑洞抽样-A类与C类.png](证据/斑洞抽样-A类与C类.png) 最后两行。
- **成因**：坐标被量化了两次——先在粗缩放下转二次曲线并取整，归一放大 s2（中位 1.27，最大 2.1）后再取整一次。审计验证：改为「一次精确仿射＋一次取整，再叠加化」后，148 个中有 142 个拓扑与源一致。
- **建议**：随脚本报告 S1（单次变换管线）一并解决，不必单独处理。清单见 [量化拓扑变化.tsv](数据/量化拓扑变化.tsv)。

## 三、斑洞疑似甄别（误报说明）

`体检报告.txt` 中列出的条目数：陈昌治 780、段玉裁 148、藤花树 94、徐锴 158，共 1180 个码位条目，合并同一字形后为 **950 个独立字形**。甄别方法不靠肉眼，而是对每个字形做**几何判定**：用 skia-pathops 求交付轮廓的孔洞（反向轮廓）及面积，再与码表源路径（`paths_1-189.json`，按非零规则叠加化）的孔洞逐一对比。

| 类 | 判据 | 独立字形 | 结论 |
|---|---|---|---|
| A | 交付轮廓中没有 < 0.004 em² 的孔洞 | 141 | **误报**：笔画近接，96px 抗锯齿把缝隙糊住、围出一小块封闭白区。高分辨率下没有封闭区，几何上也没有孔 |
| B | 有微小孔洞，且孔洞数、最小孔面积与源一致（误差 ≤15%） | 808 | **误报（设计镂空）**：码表原字形本来就有的小封闭空间，如笔画交汇处的三角空隙、「心」底部、「亘」内圈、「目」「田」中的窄格。最小孔中位约 4.7 像素@96px |
| C | 孔洞数与源不同 | 1 | 段玉裁本 U+3E186（林）：属 G9，不需要单独修 |

- 多款同时命中的 69 个码位：B 类 102 条、A 类 42 条，没有一条是真缺陷。多款同时命中，说明这是四家共有的字形结构，并不预示缺陷。
- 目检抽样：分层随机（种子 20261113），每款每类各抽若干。B 类 8 个：[斑洞抽样-B类-源字形固有.png](证据/斑洞抽样-B类-源字形固有.png)（左为 PDF 800dpi 原形，中为 OTF，右为 OTF 封闭白区标红），全部是原形中就存在的小镂空；A 类 6 个加 C 类 1 个，再加 G9 示例 1 个：[斑洞抽样-A类与C类.png](证据/斑洞抽样-A类与C类.png)，A 类高分辨率下没有微孔。
- 逐条判定见 [斑洞甄别.tsv](数据/斑洞甄别.tsv)（含孔洞数、源孔洞数、最小孔面积及折合 96px 像素）。
- **回应 v0.1.1 修复目标**：「中空」（任务 26）在 Release 中已经彻底消除。全量 42,967 个字形的墨迹面积与源相差都在 1% 以内，残余重叠为 0，没有任何字形出现成片中空。

## 五、方法与抽样说明

1. **全量**（每字都查）：空字形、包围盒与居中、宽/高约束、孔洞与碎屑、残余重叠（交付轮廓再叠加化一次，面积应不变）、与源路径对照的面积/宽高比/拓扑——工具 [几何审计.py](工具/几何审计.py)，逐字明细在 `数据/release-*.tsv`（Release）与 `数据/local-*.tsv`（本地 WIP），每款一个文件；覆盖与映射——[映射审计.py](工具/映射审计.py)；漏提归因与可回收性——[漏提诊断.py](工具/漏提诊断.py)；跨款一致性——[跨款一致性.py](工具/跨款一致性.py)（同一码位四款归一到 48×48 求两两交并比，离群 37 条，按严重度取前 8 条与 PDF 原形逐一对照，见 [跨款离群抽查.png](证据/跨款离群抽查.png)、[跨款离群-四款横排.png](证据/跨款离群-四款横排.png)：全部与原形一致，属版本字形差异，**没有配错字形**）。
2. **抽样目检**：斑洞各类按款分层随机抽样（种子 20261113）；保真度另做简单随机抽样 16 字（每款 4 个，种子 36）：[随机抽样16字-原形对照.png](证据/随机抽样16字-原形对照.png)，全部与 PDF 原形一致。由于面积、宽高比、拓扑三项已经全量普查，目检的作用是确认判定方法本身可靠，而不是替代普查。
3. **渲染链**：hb-view（HarfBuzz）、PIL/FreeType、pymupdf（PDF 真值光栅）、skia-pathops（几何），四条链互相独立。
4. **复现**：在 `fonts/` 下执行 `export UV_CACHE_DIR=$PWD/.uv-cache PYTHONDONTWRITEBYTECODE=1`，然后 `uv run --offline python audit/工具/<脚本>`。几何审计每款约 35 秒。
