## 二、专项结论

### 2.1 度量归一的数学

- 缩放 `s2 = min(0.96·UPEM/h, 0.98·UPEM/w)`（`:196`）：正确，墨迹高 96%、宽封顶 98%。
- 水平 `tx = 0.5·UPEM − w·s2/2 − rx0·s2`（`:199`）：正确。全量普查最大水平偏差 0.03% em。
- 垂直（`:200`）：**有缺陷**，即 S3。高度约束时，缩放后高＝TOP−BOT＝0.96em，顶对齐与居中等价，所以 99% 的字形没有暴露问题；宽度约束时墨迹会上浮 (0.96 − 缩放后高)/2。
- 精确墨迹包围盒用 BoundsPen 求，不受控制点影响：正确（v0.1.0 那次居中修复的成果保留着）。但包围盒会被碎屑污染（M4）。
- 全角步进：Release 全部为 2048，正确。

### 2.2 skia-pathops 叠加化与「错位陷阱」

- 叠加化用的是 `fontTools.ttLib.removeOverlaps`（skia 非零规则简化，`clockwise=path.clockwise`），它会把 lsb 同步为新的 `xMin`：用法正确。全量复查残余重叠为 0，与源面积偏差全部 < 1%，「中空」已经彻底消除。
- **现行两段式没有「彻底规避」陷阱，只是暂时没触发**（M1）。真正起作用的是「测量与变换走同一条 glyphSet 绘制路径」，与是否编译过无关。审计用实验证伪了「编译后读数就正确」的说法。
- 根治方案 R1（推荐）：**不再回读已构建的字形**。在源路径（浮点三次曲线）上用 BoundsPen 算出精确包围盒 → 一次性得到最终仿射矩阵 → 用 TransformPen 把精确坐标送入 pathops 并取整一次 → `pathops.simplify` 叠加化 → 直接写入 T2CharStringPen（CFF）。需要 TTF 时再从同一份简化路径转二次。这样一来，lsb 与 xMin 不一致、二次量化、TrueType 绕道三个问题同时消失，整条管线只需一个阶段。

### 2.3 缠绕方向

- 源 SVG 用 nonzero 规则（pdftocairo 输出的 `<use>` 没有声明 fill-rule，按默认处理），与 skia 简化时用的 winding 一致：处理完备。
- `Cu2QuPen(reverse_direction=True)` 把外轮廓转成 TrueType 惯例的顺时针；最终 CFF 外轮廓实测为逆时针（AreaPen 抽 300 个字形，有向面积全部为正），符合 PostScript 惯例。
- 唯一的隐患：如果将来某页 SVG 显式使用 `fill-rule:evenodd`，现有解析不会读取这个属性。建议在 `parse_svg` 里断言没有 evenodd。

另外，**本地 `fonts/` 下的陈昌治、徐锴、藤花树三款 OTF 是用 WIP 构建的，与 Release 不一致**，段玉裁本还没有重建。在 font-lead 落地修复之前，任何体检或宣发都应以 Release 附件（或 `zhuan/` 下的副本）为准。

## 五、建议的修复顺序（供 font-lead 落地）

1. **R1 管线重构**（同时解决 S3、M1、M2、M3，并为 M4 提供落脚点）：源路径精确包围盒（剔除碎屑）→ 一次仿射（无条件居中）→ 取整一次 → pathops 叠加化 → CFF；
2. S1、S2、S5：提取完整性（第 190 页、X/Y 编号、Q2 门禁），修好后藤花树本应恢复到 11,328 码位，其余三款各加 48–54 个；
3. S4、S6：zhuan 查表链优先级、第二层重码裁定、分款回退表、`.notdef` 画框，然后重新导出 `modern_map.tsv`；
4. 门禁 Q1–Q11 与 justfile 调整，以及 M7、L 类的度量和元数据问题；
5. 重建四款，全部门禁通过后由 desktop-lead 独立复核，再发布 v0.1.2。
